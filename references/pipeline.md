# pipeline — 六阶段制作流水线

从一篇科技/财经文章到解说成片（默认 16:9 横屏 h169；画布选择见下）。方向性判断（爆点、舞台、结构）先定，
再进入昂贵的素材生成与逐镜头渲染。

## 目录
- 阶段 0：文章理解与爆点提取
- 阶段 1：脚本创作
- 阶段 2：分镜设计
- 阶段 3：素材预生成（ComfyUI）
- 阶段 4：配音与时间轴（Edge TTS）
- 阶段 5：Remotion 渲染
- 阶段 6：自检与交付

**执行原则**：Agent 根据文章内容自主推进阶段 0–2 的创意判断并记录，不逐阶段
等待确认（除非用户要求参与）。阶段 3 出图需人工筛废片。验收贯穿全程：阶段 5
起每镜 still 自检，阶段 6 是正式过检。

**产物归属**：本次文章的脚本/素材/成片属于**项目工作目录**（默认
`work/<slug>/`），不写进 skill 本体。只有通用规则/配方卡改进才回流 skill。

---

## 阶段 0：文章理解与爆点提取

**目标**：把一篇信息密集的文章，坍缩成**一个爆点**。

**操作**：
1. 通读文章，列出所有潜在"钩子候选"：最反直觉的事实、最戳痛点的冲突、最大的
   数字反差、最有情绪张力的对立。
2. 用 `hook-and-script.md` 的"爆点筛选判据"选出**唯一**爆点。判据核心：
   - 能不能在 3 秒内让一个不懂行的人"想看下去"？
   - 有没有清晰的冲突/悬念/利益相关？
   - 是不是大众能共情的角度（而非行业黑话）？
3. 定：目标受众、情绪基调（燃/焦虑/好奇/爽）、一句话主线。
4. **判断舞台类型**（依据叙事逻辑，见 SKILL.md 三舞台）：数据对比→Slide；
   双方博弈/拟人→Theater；发展历程/因果链→Map。记录选择依据。
5. **选画布**（三预设，版式见 `layouts/h169.md`）：
   - **h169 横屏 1920×1080（默认）**：数据密集/对决/editorial 风格、3–8min 知识片、
     多平台分发（视频号+B站+西瓜）。
   - **v916 竖屏 1080×1920**：视频号信息流短爆款（1–3min）、沉浸感优先。
   - **v34 竖屏 1080×1440**：折中（信息流友好 + 略宽版式）。
   判据：分发平台 × 内容形态。横屏第一原则"左右分栏"，竖屏"上下堆叠"。

**产出**（写入 `work/<slug>/brief.md`）：爆点决策记录、钩子、受众、情绪基调、
主线、舞台类型 + 依据。

**常见坑**：贪多想覆盖全文核心信息（→ 变成朗读，完播归零）；用行业黑话当钩子
（大众看不懂）；舞台按题材写死而非按叙事逻辑选。

---

## 阶段 1：脚本创作

**目标**：把爆点写成一支 60–120s 的视频号口播稿。

**操作**：按 `hook-and-script.md` 的爆款结构写：
1. **黄金 3 秒钩子** → 2. **单点爆破**（把爆点一句话砸出） → 3. **3–5 个支撑点**
   （每个只服务爆点，用具体数字/画面感） → 4. **情绪高潮** → 5. **关注/转发引导**。
2. 硬约束：口语化、短句（每句 ≤ 一屏字幕量）、去黑话（专业词必须即时用大白话
   解释）、总时长 60–120s（按语速 ~5 字/秒估算约 300–600 字）。
3. 全稿**分短句编号**（S01, S02…），后续 TTS/字幕/分镜都以短句为原子单位。

**产出**（`work/<slug>/script.md`）：编号短句口播稿。

**常见坑**：句子太长塞不进一屏字幕；专业名词不解释；结尾没有行动引导。

---

## 阶段 2：分镜设计

**目标**：逐短句排成有能量曲线的分镜，并产出**素材需求清单**。

**操作**：
1. 读选中舞台的 `stages/<type>.md`、对应 `skins/<skin>.md`（如 Theater 的 versus）
   与全部 `sticker-cards/` frontmatter；版式按画布读 `layouts/h169.md`。
2. 逐短句填分镜表（长在 `work/<slug>/storyboard.md`）：

   `| 句号 | 口播文本 | 舞台/皮肤 | 贴纸配方卡 | 画面元素 | 关键词钉帧 | 素材需求 |`

   - **关键词钉帧**：标出该句里哪个词要触发贴纸爆出（如"暴跌`40%`"→数字滚动+红箭头）。
   - **Theater 镜头**：填角色状态表（谁在场/站位/谁打光）+ 皮肤 props；
     进出场对齐台词（`stages/theater.md`）。
   - **素材需求**：需要 ComfyUI 生成哪些背景/角色/贴纸图。
3. 能量曲线：钩子高能→支撑段高低交替→高潮峰值→结尾干净。一种贴纸手法别全片
   刷（同质化即返工信号）。Theater 按镜头选用，机制解释段回 Slide（防 P2）。
4. 反复出现的角色写进**角色设定表**（`work/<slug>/characters.md`）：每角色一张
   参考图路径 + 固定风格描述，供阶段 3 锁一致性。拟人化方法见 `character-design.md`。

**产出**：分镜表、素材需求清单、角色设定表。

**常见坑**：分镜放行前就去生成素材（画面状态未定，重复生成）；关键词钉帧漏标
（音画对不齐）；同一贴纸手法全片重复。

---

## 阶段 3：素材预生成（ComfyUI）

**前置**：分镜与素材清单已定。

**目标**：一次性生成所有静态素材，渲染时只用图不再出图。

**操作**（细节见 `comfyui-assets.md`）：
1. 起本地 ComfyUI（HTTP）。`scripts/comfyui_client.py` 按素材清单批量提交 prompt。
2. **角色一致性**：同一角色跨镜头用**参考图**锁定（IPAdapter/参考图 workflow），
   固定风格描述与 seed 策略；生成后人工筛掉废片、跨镜头挑出一致的一组。
3. 背景/贴纸/角色分类存进 `work/<slug>/assets/`，文件名与分镜素材需求对齐。
4. 透明底贴纸用 PNG alpha；需要"飞入空板"的镜头额外出空背景。

**产出**：`work/<slug>/assets/` 分类静态素材；一致性已人工确认的角色图组。

**常见坑**：渲染时才实时出图（慢、有废片率、会卡管线）；角色跨镜头不一致；
忘了透明底。

---

## 阶段 4：配音与时间轴（Edge TTS）

**前置**：脚本定稿（阶段 1）。可与阶段 3 并行。

**目标**：拿到逐句音频 + 词级时间戳，回填成帧级时间轴——这是全 skill 最关键工程。

**操作**（细节见 `tts-timing.md`）：
1. `scripts/tts_client.py` 对每个短句**独立合成**（后端 `edge`，音色见 tts-timing）：
   产出 `work/<slug>/audio/S01.mp3 …` + 每句的 WordBoundary 词级时间戳 json。
   单句失败只重试该句（应对 Edge 偶发限流）。**中文必须 `boundary='WordBoundary'`**。
2. ffprobe 量每句实际时长。
3. `scripts/build_timeline.py` 合成 `work/<slug>/timeline.json`：
   - 每句的起止帧（30fps，按累计音频时长换算，句间可留呼吸间隔）
   - **字幕锚点**：句内每个词的 `{word, fromFrame, toFrame}`
   - **字幕分组 chunks**：按 ≤13 字把词切成显示组（去标点、尾部再平衡避免孤字屏），
     字幕一屏一组、逐组跟随口播
   - **贴纸钉帧锚点**：分镜标的关键词 → 对应词的时间戳帧号
4. 拼接整条口播音轨（含句间停顿）供 Remotion 用。

**产出**：`audio/` 逐句音频 + 整轨；`timeline.json`（帧级 + 词级 + 钉帧锚点）。

**常见坑**：写死镜头帧数不按音频反推；忘留句间呼吸；词级时间戳单位没换算
（Edge 是 100ns）；整篇一次合成导致一处失败全废。

---

## 阶段 5：Remotion 渲染

**前置**：可跑的 Remotion 工程（30fps，画布由 timeline.json 的 `canvas` 字段决定，
默认 h169 1920×1080，`src/index.ts` 注册 Composition）；素材（阶段 3）与
timeline.json（阶段 4）就绪。

**目标**：按时间轴逐镜头落地，每镜完成即自检。

**操作**：
1. 选中舞台 → copy 对应 `components/stage/<Type>Stage.tsx` + 用到的
   `components/stickers/*` + `components/skins/*`（Theater 皮肤）+
   `KaraokeCaption.tsx` 进工程。
2. 读 `timeline.json`：句边界定镜头时长，词级锚点喂 KaraokeCaption 做逐词高亮，
   钉帧锚点触发贴纸爆出；`canvas` 决定安全区/字幕参数（layouts/h169.md）。
3. **每镜抽卡适配**：读配方卡全文 + 组件，按内容改参数（不降配方卡"命门"参数档）。
4. **静帧验收**：每镜 `npx remotion still` 出帧，肉眼查构图/字幕锐度/穿帮。
5. **每轮整片渲染** + ffmpeg 抽帧回看。字幕硬烧（见 caption-rules.md）。
6. 确定性渲染：固定种子。
7. **封面**：用 `Cover` composition 渲独立封面 `out/cover.png`（画布与正片一致）——
   钩子 ≤8 字、超大字、主贴纸占屏 40%+，不依赖视频首帧（规则见 douyin-video-rules H4）。
8. **SFX（可选）**：对决/重击类镜头用 `assets/sfx/` 音效按帧触发（volume ≤0.6），
   不做 BGM。

**产出**：整片 mp4（每轮一版）+ `out/qa/` 静帧 + `out/cover.png`。

**常见坑**：跳过配方卡自己写（回踩已知坑）；字幕太小（静音刷看不见）；
贴纸没卡在关键词上；镜头时长与音频不符。

---

## 阶段 6：自检与交付

**目标**：对照 `douyin-video-rules.md` 逐条过检，出带帧号报告，再终渲。

**操作**：
1. 整片渲染，ffmpeg 抽关键帧（每镜至少：入场、动作峰值、落定）。
2. 逐条过爆款准则：钩子够狠吗（黄金3秒）、有无哑巴段落、字幕可读性、音画钉帧
   对齐、完播卡点、一种手法有无被重复、结尾引导。格式 `编号 ✓/✗(句号/帧号)`。
3. 音画对齐终检：逐句 SFX/贴纸对帧回放，确认无错位。
4. 修复回小循环：结构问题回阶段 1/2，画面回阶段 5，配音回阶段 4。
5. 终渲交付：**双件套**——`promo.mp4` 成片 + `cover.png` 封面（画布一致）
   （如需另出无 BGM 版，用 inputProp 从同一时间线渲）。

**产出**：自检报告（准则 checklist + 帧号证据）+ **成片 + 封面图**。

**常见坑**：自检报告全 ✓ 无证据；把验收留到最后一次做；钩子不够狠却放行。
