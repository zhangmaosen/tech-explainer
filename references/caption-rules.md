# caption-rules — 字幕（卡拉OK式句内词高亮）规范

通用规范，不含具体文案。字幕是视频号完播的命门（大量用户静音刷）。

## 一、显示模式（chunking 分组）
- **一屏一组（≤13 字）**：字幕不按整句显示——build_timeline.py 把每句的词按 ≤13 字
  切成显示组（chunks），口播走到哪组就显示哪组。长句绝不整句 3–4 行堆屏
  （v1 判例：96px 字体 + 25 字句 = 4 行字幕压住画面）。
- **组内逐词高亮（卡拉OK式）**：组内当前朗读词高亮 —— 词级时间戳驱动。三态：
  - 已读词：常态色（如浅灰白）
  - 当前词：高亮色 + 轻微放大（scale 1.14）+ 描边
  - 未读词：常态色（可略暗）
- **字幕去标点**（解说号惯例）；标点只用于口播停顿与 chunking 切分。

## 二、可读性硬指标（按画布预设，默认 h169 横屏）
画布由 timeline.json 的 `canvas` 字段决定，组件参数见 helpers 的 `CANVAS` 预设，
版式细则见 `layouts/h169.md`（横屏）与其附录（竖屏存档）。

| 指标 | h169 (1920×1080) | v916 (1080×1920) |
|---|---|---|
| 口播字幕标准字号 | 72px | 72px |
| 字幕容器 | x=120, w=1680, y=940 | x=30, w=1020, y=1420 |
| 内容安全区 | y 140–900, x 120–1800 | y 420–1280 |
| 辅助文字 | ≥58px | ≥58px |

- 72px 是实片验证档：96px 会导致一行仅 9–10 字、长句堆 3–4 行（v1 判例）。
  横屏手机全宽播放时 72px 的物理大小与竖屏相当。
- 每组 ≤13 字，最多 2 行——这是**节奏规则不是宽度规则**，横屏也不放宽。
- **关键词高亮态可更大**。
- **强描边或半透明底 scrim**：字压在任何背景上都要有足够对比度（描边 4–6px 或
  背景暗化块）。
- **安全区**：横屏字幕带压底（y≈940–1010），避开播放器控件；竖屏放下三分之一
  偏上（y≈1250–1550）。核心贴纸始终放内容安全区内。

## 三、样式建议
- 字体：粗黑体/圆体，笔画厚（细字在小窗糊）。见 `assets/fonts/`。
- 每屏字数：中文 ≤14 字/行、≤2 行；超了必须在阶段 1 拆句。
- 高亮色与全片情绪基调一致（燃→暖橙/金；焦虑→红；科技→青蓝）。

## 四、KaraokeCaption 组件契约
组件 `components/caption/KaraokeCaption.tsx` 输入：
```ts
{ chunks: { fromFrame, toFrame, text, words: { text, fromFrame, toFrame }[] }[],
  activeColor, idleColor, readColor, fontSizePx=72, strokePx=4,
  x=30, y=1420, width=1020 }  // x/y/width 由舞台按 CANVAS 预设注入
```
按 `useCurrentFrame()` 选当前组，组内判断每个词三态。chunks 来自 timeline.json
（build_timeline.py 的 chunk_words 产出，含去标点与尾部再平衡）。

## 五、自检
- [ ] 一帧缩到 480px 宽（模拟手机），每句读得清？
- [ ] 高亮词跟着口播逐词走？
- [ ] 字幕没被顶部/底部安全区裁到？
- [ ] 字高达标（口播≥72px / 辅助≥58px，量渲染帧实际像素）？
