# stages/map — 地图引导类舞台设计规范

**隐喻**：一张大画布（俯视/斜俯视地图），镜头沿路径平移+缩放，节点讲段落。
**适用叙事**：流程、发展史、因果链条、"一步步带你走"、路线之争。
**难度**：★★★★（镜头路径与口播节奏同步 + 缩放清晰度）。

## 空间模型
- 一张远大于屏幕的地图画布（如 3000×6000），若干**节点**（贴纸）分布其上。
- 一个"镜头/主角"在地图上移动：镜头平移到节点 → 停下放大讲该段 → 移向下一节点。
- 层：地图底 → 路径线 → 节点贴纸 → 当前节点高亮/信息卡 → 字幕（屏幕固定层）。

## 镜头运动（核心难点）
- **镜头跟随口播**：一句/一段口播对应"平移到某节点 + 缩放停留"。移动发生在句间
  过渡，讲解发生在停留时。移动/停留帧从时间轴句边界划分。
- **缩放清晰度**：放大时节点素材要够分辨率（预生成时按放大倍数出高清图，或用
  矢量/大字），否则糊——参考 video-shotcraft Q2 的教训。
- **路径可视**：走过的路径线点亮，暗示进度。

## 与时间轴对接
- 句边界 = 到站/离站切换。pins 的关键词帧触发节点信息爆出。
- 镜头平移用缓动（非匀速），到站 hold 跟着音频停留时长。

## 组件（里程碑3 实现）
`components/stage/MapStage.tsx`：管理地图画布、镜头 keyframe（平移+缩放）、节点、
路径点亮；字幕保持屏幕固定层。

## 常见坑
- 镜头匀速平移（廉价 PPT 感）。
- 放大节点糊（素材分辨率不够）。
- 镜头运动和口播节奏错位（走还没讲完/讲完还没到）。
- 节点太多一屏塞满。
