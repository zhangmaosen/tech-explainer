# hook-and-script — 爆点提取与视频号爆款脚本方法论

本文件是**通用方法论**，不含任何具体文章内容。对任意科技/财经文章适用。

## 一、爆点提取

一篇文章通常有很多信息点，但一支视频号视频只能有**一个爆点**。爆点 = 能让一个
**不懂行的普通人**在 3 秒内产生"我想看下去"冲动的那个核心张力。

### 爆点候选类型（从文章里找这几种）
- **反直觉事实**：与大众常识相反（"你以为 X，其实 Y"）。
- **利益冲突/博弈**：两方对立、谁赢谁输（国家竞赛、公司对决、路线之争）。
- **巨大数字反差**：极端的大/小/快/贵/差距（成本降到 1/100、领先 8 年）。
- **悬念/未知**：结局未定、命运攸关（谁能率先突破、能不能成）。
- **痛点共情**：与观众切身相关（钱、工作、安全、未来）。

### 筛选判据（选唯一爆点）
逐个候选问三个问题，全 yes 才留：
1. **3 秒可懂**：不懂行的人能瞬间 get 到张力吗？（需要背景知识才懂的 → 淘汰）
2. **有冲突/悬念/利益**：它自带"想知道后续"的拉力吗？
3. **大众角度**：能翻译成人人有共鸣的语言吗（而非行业黑话）？

多个候选都合格时，选**情绪张力最大、最能一句话说清**的那个。其余信息点降级为
"支撑爆点的论据"或直接砍掉。

### 爆点 → 主线
把选中的爆点写成**一句话主线**（全片都为这句服务）。形如：
"[主体] 正在 [做一件反直觉/高张力的事]，而这决定了 [与观众相关的大结果]。"

## 二、视频号爆款脚本结构（六段式）

科技/财经解说的完播率 = **钩子（留住人）× 知识获得感（值得看完）**。
只做钩子不做获得感，成片会像新闻播报一样平淡。

固定六段式（时长 60–120s，语速约 5 字/秒 → 约 300–600 字）：

### 1. 黄金 3 秒钩子（开头第一句）
决定完播率的生死线。钩子公式（任选其一，可叠加）：
- **疑问式**："为什么 [反直觉现象]？"
- **反差式**："别人还在 X，它已经 Y 了。"
- **利益式**："这件事，直接关系到你 [钱/工作/未来]。"
- **冲突式**："一场 [谁 vs 谁] 的暗战，已经打响。"
- **数字式**："[极端数字] —— 这个数字背后……"

钩子禁忌：不要用"大家好""今天我们聊聊"这类冷启动；不要先铺背景；第一句就要爆。

### 2. 单点爆破（钩子之后 1–2 句）
把爆点/主线一句话砸实，让观众明确"这视频到底在讲什么值得看的事"。

### 3. 机制解释段（科技类必配，"原来如此"时刻）
**用大白话 + 类比，讲清一个核心原理/机制**——这是科技解说的灵魂段落，观众的
"学到了"感主要在这里产生。写法：
- 先讲"它怎么工作"（机制），再讲"为什么难/为什么牛"（门槛）。
- 必须用**类比**翻译原理（"像边开车边漏油""金属自己都会烧起来"）。
- 时长占比约 15–25%，是全片信息密度最高的一段，也是最能引发转发的段落。
- 判据：观众看完能不能转述"哦原来它是这么回事"。不能就是没讲透。

### 4. 硬核支撑点（2–4 个，主体）
每个支撑点**只服务爆点**，且必须满足"谈资三性"（见下"知识点设计"）：
- 高低能量交替，别一路平铺。
- 支撑点之间用"承接钩子"过渡（"但真正的问题是……""更狠的还在后面……"）保持拉力。

### 5. 情绪高潮（1–2 句）
把爆点的意义推到最大：格局、悬念、结局、与观众的关系。

### 6. 关注/转发引导（结尾 1 句）
给一个明确行动理由（"想看后续进展，点个关注""你觉得谁会赢，评论区聊聊"）。

## 三、知识点设计（科技类强制）

每支科技解说必须配齐三层知识密度，缺一不可（自检见 douyin-video-rules H5/C4）：

### 1 个机制解释（"原来如此"）
全片只讲透**一个**核心机制，不贪多。讲透 = 有类比 + 有"为什么难"。

### 2–4 个谈资级硬核点
从文章里挖**具体、意外、有名有姓**的知识点——观众看完能拿去当谈资：
- **有名有姓**：具体的技术名/材料名/项目名（而非"很先进的技术"）。
- **有意外性**：违反直觉的细节（"金属自己会烧起来"）。
- **有画面感**：能在脑子里成像的过程（"制造周期从两个月缩到两天"）。

### 大数字必须具象化翻译
干数字直报 = 无效信息。每个大数字给大众可感的类比：
- 压力 → "相当于多少米深海/多少个大气压"
- 重量/推力 → "相当于举起多少辆坦克/汽车"
- 成本 → "相当于多少套房/多少杯咖啡"
- 速度/尺寸 → 与熟悉物对比
判据：这个类比能让不懂行的人"哇"出来吗？

### 硬核 ≠ 黑话堆砌
每个硬核点过"转述测试"：能转述给不懂行的朋友且对方能听懂吗？不能就继续
翻译或砍掉。黑话出现必须**当场**用大白话解释。

## 四、写稿硬约束（写完自检）
- [ ] 第一句是不是 3 秒钩子，而不是背景/问候？
- [ ] 全片只有一个爆点吗？支撑点都在服务它吗？
- [ ] （科技类）有没有一个讲透的机制解释段？有没有 2–4 个谈资级硬核点？
- [ ] 每个大数字都有具象化翻译吗？
- [ ] 每个专业词都当场解释了吗？
- [ ] 句与句之间有承接钩子吗？
- [ ] 总时长在 60–120s 吗（字数 300–600）？
- [ ] 结尾有明确行动引导吗？
- [ ] 全稿已按短句编号（S01…）？

## 五、分短句规则（与字幕 chunking 配合）
- 一句 = 一个语义单元，口播一口气能说完。
- **TTS 按自然句合成**（保证韵律），**字幕显示由 chunking 按 ≤13 字分组**——
  所以写稿时句子可稍长，但**必须有干净的标点切分点**（逗号/顿号），
  让 chunking 能在词边界处断。一口气 20+ 字无标点的长句要避免。
- 字幕文本**去标点**（解说号惯例），标点只用于口播停顿和 chunking 切分。
- 每句编号 S01、S02……贯穿全流程。
